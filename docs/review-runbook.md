# Runbook: цикл ревью и самообучения вопросов

Самодостаточная инструкция по замкнутому циклу «генерация → судья → моё ревью →
доработка → обучение пайплайнов». Цель — чтобы моё ревью требовалось всё меньше.

## Два хранилища

| Файл | Что | Кто читает |
|---|---|---|
| `public/questions.json` | **ПРОД** — только `approved` | игра + админка |
| `data/review-pool.json` | **ПУЛ** — всё на ревью | только админка (dev) |
| `data/review-log.jsonl` | журнал моих действий (корпус для анализатора) | анализатор |
| `data/.analyzer-watermark.json` | водяной знак `lastAnalyzed` | анализатор |

Игра показывает **только** `approved` из прода. Всё остальное — в пуле, в сборку не идёт.

## Статусы (`reviewStatus`)

`pending` (не смотрел) · `approved` (Хорошо) · `rework` (На доработку) · `discard` (На выброс).

## Цикл

### 1. Генерация → пул
```
node scripts/prep-... / см. docs/generation-runbook.md
Workflow fill-questions.workflow.js
node scripts/merge-gen.mjs        # льёт результат в ПУЛ как pending + llmVerdict
```

### 2. Ревью в админке
`npm run dev` → http://localhost:5173/admin.html

В карточке: LLM-вердикт (read-only) · мой вердикт (**Хорошо / На доработку / На выброс**) ·
**Проблема** и **Предложение** (пишу только я) · чипы причин · кнопка **Редактировать**
(ручная правка текста). Клавиши `A`/`R`/`D`.

### 3. Батч-операции
Кнопки вверху админки (или CLI):
```
node scripts/promote-to-prod.mjs   # approved из пула → прод (с код-гейтами)
node scripts/delete-drops.mjs      # удалить discard из пула
```
Перенос в прод — **только по моей команде** (кнопка/CLI), не автоматически.

### 4. Доработка (rework → polish → пул)
```
# кнопка «На доработку» (или экспорт rework в scripts/polish-in)
Workflow polish.workflow.js
node scripts/merge-polish.mjs      # возвращает в ПУЛ: pending + reworkedAt + «было»
```
Доработанные приходят с бейджем «прошёл доработку» и сохранённой `preReworkVersion` —
пере-ревьюй и реши Хорошо / снова доработка / выброс.

### 5. Обучение (пачкой, не после каждого ревью)
```
node scripts/prep-analysis.mjs            # журнал после водяного знака → analysis-in
Workflow analyze-reviews.workflow.js      # тренды → примеры + предложения правок
node scripts/merge-analysis.mjs           # примеры → quality-examples.md (аддитивно);
                                          # предложения → docs/rubric-proposals/<date>.md;
                                          # сдвигает водяной знак
```
**Свод `docs/category-risks.md` правлю руками** по предложениям из `rubric-proposals/` —
анализатор его не трогает (финальное слово за человеком).

## Принципы

- В прод едет только то, что я одобрил.
- «Хорошо» = корпус «как надо» (= прод). Мои правки/доработки/дропы = корпус «как НЕ надо»
  (журнал → примеры).
- Анализатор *предлагает* правки правил, *применяю* их я.
- Общий слой операций прод/пул — `scripts/lib/review-store.mjs` (его делят dev-плагин Vite
  и CLI-скрипты), чтобы логика жила в одном месте.
