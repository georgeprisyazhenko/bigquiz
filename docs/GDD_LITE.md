# BigQuiz — GDD Lite / Game Specification v1.3

## 1. Общая информация

**BigQuiz** — веб-викторина с бесконечной подачей случайных вопросов. Игрок сразу попадает на игровой экран, видит изображение, текст вопроса и 4 варианта ответа. Нужно выбрать 1 правильный ответ.

**Платформа:** веб-игра для Яндекс Игр
**Текущий статус:** код MVP собран, SDK интегрирован
**Стек:** Phaser + JavaScript + Yandex Games SDK
**Интерфейс MVP:** десктоп / горизонтальный экран (1120×640 px)

---

## 2. Основной игровой цикл

1. Игрок открывает игру.
2. Параллельно: инициализируется SDK, загружаются шрифты, загружаются questions.json и categories.json.
3. После загрузки сразу виден основной экран с вопросом.
4. На экране: вкладки режима (вверху), карточка вопроса (центр), правая панель (рекорд + рейтинг).
5. Игрок выбирает один из 4 вариантов ответа.
6. Ответ фиксируется, сменить его нельзя.
7. Показывается правильный ответ; неправильный вариант подсвечивается красным.
8. Остальные варианты получают приглушённый вид.
9. Начисляются очки (100 × множитель) и обновляется статистика.
10. Через **1.5 секунды** — следующий вопрос или полноэкранная реклама через SDK (каждые 5 ответов).

---

## 3. Основной экран

**Вкладки режима (y=16, ширина = ширина карточки):**
* три режима: «Случайный вопрос», «Блиц», «Уверен?»;
* активная вкладка выделяется цветом темы режима;
* переключение на вкладку «Блиц» открывает экран-приглашение забега (см. §7).

**Карточка вопроса (580×552 px, центрирована, y=72):**
* категории текущего вопроса — компактные чипы (graphite);
* текст вопроса (макс. 240 символов, обрезается до высоты QUESTION_HEIGHT);
* изображение 4:3 (333×250 px), скруглённые углы (единый радиус `UNIFORM_RADIUS`), без рамки, cover-вписка;
* 4 варианта ответа в сетке 2×2.

**Правая колонка (справа от карточки, x = CARD_X + CARD_WIDTH + 30):**
* «РЕКОРД» — максимальная серия правильных ответов за сессию;
* кнопка «Рейтинг» — открывает оверлей лидерборда.

**Примечание:** кнопка звука (renderSoundToggle) реализована, но пока не подключена к renderScreen — отображается только при явном вызове.

## 4. Вопросы и структура

```json
{
  "id": "q_001",
  "question": "Какой организм способен переходить в состояние криптобиоза?",
  "answers": ["Тихоходка", "Дафния", "Планария", "Морская звезда"],
  "correctAnswerIndex": 0,
  "categories": ["priroda-zhivotnye", "biologiya"],
  "image": "assets/images/q_001.jpg",
  "imageRole": "illustrative",
  "requiresImage": false,
  "explanation": "Тихоходки впадают в криптобиоз — почти полностью останавливают обмен веществ и переживают вакуум, радиацию и −270 °C.",
  "imageSearchQuery": "Криптобиоз"
}
```

**Поля:**
* `categories` (1–3) — `id` подкатегорий или верхней категории из `categories.json` (отдельных тегов нет);
* `explanation` — «факт-награда»: короткое объяснение, почему верный ответ верен (показывается при ответе, даёт эффект «о, интересно, буду знать»);
* `imageSearchQuery` — поисковый запрос для подбора картинки (используется позже при наполнении изображениями).
* `reviewStatus` / `reviewNote` — метаданные локальной админки ревью (`pending`/`approved`/`rejected` + заметка). Опциональны, игра их не использует. См. `admin.html` (только dev).

**Требования к вопросу:**
* максимум 240 символов (желательно до 160);
* ровно 4 варианта ответа;
* только 1 правильный ответ;
* неправильные варианты — правдоподобные, но однозначно неверные;
* `explanation` обязателен для новых вопросов (валидатор предупреждает, если его нет).

## 5. Изображения

**Размеры:**
* Рекомендуемый: 1332×1000 px (4:3, горизонтальная)
* Минимальный: 666×500 px
* Форматы: JPG, JPEG, PNG, WebP, GIF

**Роль изображения:**

`requiresImage: false` — иллюстративное (при ошибке показать заглушку BigQuiz)
`requiresImage: true` — связанное напрямую (при ошибке заменить вопрос)

**Загрузка:** browser `Image()` API пробует все форматы подряд (jpg → jpeg → png → webp → gif). Текстура запекается через offscreen-canvas с обрезкой по clip-path (cover + скруглённые углы). Хранится как Phaser-текстура `question_image_<id>`.

## 6. Категории

Загружаются из **`public/categories.json`** через `buildCategoryIndex()`. Строит плоский индекс `id → name` (включая подкатегории). Если файл отсутствует/невалиден — индекс пустой, кросс-ref проверка в валидации тихо пропускается.

Предварительные категории (id → рус. название):
1. animals → Животные
2. plants → Растения
3. science → Наука
4. history → История
5. geography → География
6. space → Космос
7. technology → Технологии
8. human → Человек
9. records → Рекорды
10. culture → Культура

**Правила:**
* у вопроса 1–3 категории;
* несколько категорий ставятся только при пересечении тем.

## 7. Игровые режимы

Переключаются через вкладки над карточкой. Смена режима — немедленно (без сброса вопроса, `renderScreen(false)`).

### «Случайный вопрос» (синяя тема, `#8bcafc`)
* Бесконечная подача случайных вопросов без повторений в сессии.

### «Блиц» (фиолетовая тема, `#a08cf0`)
Забег на **60 секунд**: ответить на как можно больше вопросов; результат забега — число правильных ответов. Жизненный цикл (`blitzPhase`):

1. **`intro`** — переключение на вкладку показывает в карточке приглашение «Ответь на как можно больше вопросов за 60 секунд», рекорд блица (если есть) и кнопку «Старт».
2. **`countdown`** — отсчёт 3-2-1 по центру карточки (`this.time.addEvent`).
3. **`running`** — таймер запущен (`BLITZ_DURATION_MS = 60000`, тик `BLITZ_TICK_MS = 100`). Вверху карточки — **HUD-полоса**: слева время `M:SS` + убывающая шкала (краснеет на последней трети), справа счётчик `✓ N`. Категории/вопрос сдвинуты вниз на `BLITZ_CONTENT_OFFSET`, изображение ужато до 280×210 (4:3). Между вопросами пауза `NEXT_QUESTION_DELAY_BLITZ_MS = 400`; рекламы внутри забега нет.
4. **`result`** — по истечении времени: гашение таймера, фиксация рекорда (`blitzBest`), **полноэкранная реклама один раз**, затем оверлей результата (правильных / точность / рекорд) с кнопками «Ещё раз» и «В случайный режим».

HUD обновляется на месте по тику таймера (не через `renderScreen`, чтобы не разрушать кнопки ответов). Таймер ставится на паузу при сворачивании вкладки (`setupLifecycle`). Выбор 10/30/50 и dropdown — **удалены**.

**Время и резюм:**
* Таймеры (отсчёт и забег) считаются по `performance.now()` (реальные часы), а Phaser-событие используется лишь как тик перерисовки — иначе на лагах сразу после загрузки Phaser-дельта занижает время и таймер идёт медленнее реального.
* Незавершённый забег сохраняется в `localStorage` (`bigquiz_blitz_state`: фаза, остаток времени, счётчики, текущий вопрос и порядок ответов, `shownQuestionIds`). При обновлении страницы забег **восстанавливается с того же места**; таймер **замирает** на время перезагрузки (остаток фиксируется в `beforeunload`/при паузе). Состояние снимается при завершении забега и при уходе из режима.

### «Уверен?» (оранжевая тема, `#f0905a`)
* **Статус:** специальная механика — в разработке.

## 8. Система очков и множителей

За каждый правильный ответ: `gainedPoints = 100 × multiplier`.

**Множитель серии (`getMultiplier(streak)`):**

| Серия правильных | Множитель |
|------------------|-----------|
| 0–2              | ×1        |
| 3–5              | ×2        |
| 6–8              | ×3        |
| 9–11             | ×4        |
| 12+              | ×5        |

Формула: `Math.min(1 + Math.floor(streak / 3), 5)`

При неверном ответе серия сбрасывается, множитель возвращается в ×1.

`spawnScorePopup()` — плавающий «+100» / «+200 ×2» — реализован, но пока не вызывается (мёртвый код; подключить в `refreshScorePanel` когда появится `scoreText`).

## 9. Статистика сессии

**Хранится в состоянии:**
* `score` — текущие очки;
* `bestScore` — рекорд по очкам (персистируется через SDK);
* `correctCount`, `wrongCount`, `answeredCount`;
* `accuracy` — % правильных (считается, но не выводится в UI);
* `currentStreak`, `maxStreak`;
* `shownQuestionIds` — не повторять вопросы;
* `questionsSinceAd` — счётчик для рекламы;
* `sessionId`.

**Статистика забега Блица (отдельно от сессионной):**
* `blitzCorrect`, `blitzAnswered` — правильных / всего за текущий забег;
* `blitzBest` — рекорд по числу правильных за забег (персистируется через SDK);
* `blitzTimeLeftMs` — остаток времени забега.

**На экран выводится:**
* РЕКОРД (maxStreak) — в правой колонке, обновляется мгновенно после ответа;
* в Блице (running) — таймер `M:SS` + шкала и счётчик `✓ N` в HUD-полосе карточки.

**На экран НЕ выводится:**
* счётчик очков (scoreText = null, не отрисован);
* % точности;
* текущая серия.

## 10. Сохранения и рекорд

`persistRecord()` вызывается при каждом улучшении `maxStreak` или `bestScore` (лимит: не чаще нужного, защита от 60/мин SDK).

Сохраняется объект `{ bestScore, maxStreak, blitzBest }`:
* Гость: `ysdk.getStorage()` (localStorage-фасад SDK).
* Авторизован: дополнительно `player.setStats()`, при загрузке — `max(local, cloud)`.
* `blitzBest` сохраняется при завершении забега, если число правильных превысило прежний рекорд.

## 11. Авторизация и лидерборд

**Авторизация:**
* Silent на старте (`getPlayer()` без диалога).
* `openAuthDialog()` — только по кнопке «Войти» внутри оверлея рейтинга.
* Гость видит всю игру без ограничений.

**Лидерборд:**
* Кнопка «Рейтинг» в правой колонке открывает Phaser-оверлей.
* Таблица: `ysdk.leaderboards.getEntries(LEADERBOARD_ID, { quantityTop: 10, includeUser: true, quantityAround: 3 })`.
* Гостю показывается экран с предложением войти + выгода.
* После авторизации в оверлее — мердж рекорда и отображение таблицы.
* `LEADERBOARD_ID = 'best_streak'` (должен быть создан в Консоли: числовой, сортировка по убыванию).

| Метод | Когда |

| `LoadingAPI.ready()` | После первого `renderScreen()` |
| `GameplayAPI.start()` | При старте, после рекламы, после закрытия лидерборда |
| `GameplayAPI.stop()` | Перед рекламой, при открытии лидерборда |

## 13. Реклама

### Полноэкранная (каждые 5 вопросов)
* `ysdk.adv.showFullscreenAdv({ onClose, onError })` — платформа рисует блок сама.
* Перед показом: `GameplayAPI.stop()`, `muteSound()`.
* После закрытия (в т.ч. при `wasShown=false` и ошибке): `afterAd()` → следующий вопрос.
* Mock-оверлей «Реклама / Продолжить» — **удалён**.

### Блиц
* Внутри 60-секундного забега рекламы **нет** (чтобы не «съедать» время).
* Полноэкранная реклама показывается **один раз** при завершении забега (`showBlitzAd`), затем оверлей результата.

### Sticky-баннер
* `adv.showBannerAdv()` вызывается в `initSdkFeatures`.
* Требует включения монетизации РСЯ в Консоли.

## 14. Логирование

**Единый слой** (`logEvent(name, payload)`) — `console.log('[BigQuiz event]', {...})`.

Ключевые события: `game_load_started`, `game_loaded`, `lang_detected`, `question_shown`, `answer_selected` (с `score`, `gainedPoints`, `multiplier`, `mode`), `mode_switched`, `blitz_started`, `blitz_finished` (с `correct`, `answered`, `accuracy`, `blitzBest`, `isRecord`), `ad_requested`, `ad_closed`, `sound_toggled`, `leaderboard_opened`, `auth_dialog_dismissed`, `page_leave`.

---

## 15. Рендеринг (HiDPI / Retina)

Phaser canvas создаётся `GAME_WIDTH * RESOLUTION` × `GAME_HEIGHT * RESOLUTION` физических пикселей; камера зуммируется обратно на `RESOLUTION`. Логические координаты остаются 1120×640.

```js
const RESOLUTION = Math.min(Math.max(Math.ceil(FIT_SCALE * devicePixelRatio), 2), 4)
```

Весь текст создаётся с `{ resolution: RESOLUTION }`. Изображения запекаются в offscreen-canvas с тем же коэффициентом.

## 16. MVP НЕ включает

* главное меню, выбор категорий;
* экран результата, паузу, выход;
* пропуск вопроса, смену ответа;
* очки на экране (scoreText пока null);
* авторизацию без явного действия пользователя;
* rewarded-рекламу;
* мобильную портретную раскладку;
* механику режима «Уверен?» (в разработке).
