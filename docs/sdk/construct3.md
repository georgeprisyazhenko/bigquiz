Источник: https://yandex.ru/dev/games/doc/ru/sdk/construct-3/

## 1. Начало работы (construct-3/about)

### Purpose

YandexGamesSDK описывается как "плагин для движка Construct 3, предоставляющий удобный доступ к API Яндекс Игр."

### Installation Steps

Процесс настройки включает две фазы:

1. **Plugin Installation:**
   - Загрузите последнюю версию с GitHub
   - Откройте Construct 3
   - Перейдите в Menu → View → Addon Manager
   - Выберите "Install new addon" и выберите файл `.c3addon`

2. **Project Integration:**
   - Щелкните правой кнопкой мыши на layout
   - Выберите "Insert new object"
   - Найдите YandexGamesSDK в разделе Platform-specific
   - Нажмите Insert

### Plugin Capabilities

SDK предоставляет:
- Visual blocks для полного взаимодействия Яндекс Игр
- Опции интеграции JavaScript
- Функции локализации текста и спрайтов
- Утилиты для разработки

### Important Note

Документация отмечает, что "подключение SDK является обязательным условием для успешного прохождения модерации."

## 2. Адаптивный текст (construct-3/adaptive-text)

### Overview

AdaptiveText — это дополнительный плагин для Construct 3, который включает отзывчивое отображение текста. Инструмент "адаптирует длинные никнеймы игроков, которые не помещаются на экран, и тексты, которые стали длиннее после локализации."

### Key Features

Плагин автоматически регулирует текст для соответствия определённым границам, демонстрируя два основных варианта использования:
- Масштабирование контейнеров текста при сохранении видимости содержимого
- Динамическое уменьшение размера шрифта по мере увеличения длины текста

### Getting Started

**Installation:** Загрузите последнюю версию с [официального GitHub репозитория](https://github.com/yandex-games-plugins/construct3/releases).

## 3. Реклама (construct-3/ads)

### Key Ad Types

**Rewarded Video Ads**: Пользователи получают внутриигровые награды за просмотр видео. Реализуется через действие "Show rewarded ad" с опциональными параметрами ID.

**Fullscreen Ads**: Отображаются между действиями пользователя (переходы уровня, навигация меню). Обычно требуют минимальной дополнительной логики помимо первоначального вызова.

**Sticky Banners**: Постоянные баннеры, настроенные в Developer Console. Могут быть расположены вверху/внизу на мобильных, вверху/внизу/справа в альбомной ориентации или справа на десктопе. Разработчики могут контролировать видимость через действия "Show sticky-banner" и "Hide sticky-banner".

### Important Guidelines

Документация подчеркивает: "не вызывайте показ рекламы во время геймплея, когда пользователи могут непреднамеренно кликнуть," так как это запускает обнаружение мошенничества и уменьшает доход.

Рекомендуемое размещение объявлений происходит перед геймплеем, во время переходов между уровнями или после проигрыша.

## 4. Авторизация и данные игрока (construct-3/authorization-and-data)

### Player Information

Разработчики могут получить данные профиля игрока, используя действие **Request Player Information** вместе с условиями срабатывания. Доступные данные включают:

- **Authorization status**: проверяет, авторизован ли игрок в Яндексе
- **Player name, avatar, and unique identifier** как строковые выражения
- **Payment activity status** указывает историю транзакций пользователя
- **Personal data access verification** для подтверждения согласия

### In-Game Data Management

Пять основных действий обрабатывают прогресс и статистику игрока:

1. **Retrieve player data** — получает сохраненное состояние игры в JSON формат
2. **Save player data** — передает состояние на серверы Яндекса
3. **Fetch numerical data** — загружает числовые значения специфично
4. **Store numerical data** — сохраняет числовые значения на серверах
5. **Increment numerical data** — добавляет указанные суммы к существующим числам

### Critical Consideration

"Все эти действия — асинхронные и их срабатывание занимает какое-то время" (All actions are asynchronous). Разработчики должны реализовать команду **Wait for Previous Actions** для предотвращения ошибок от преждевременного доступа к данным.

## 5. Удаленная конфигурация (construct-3/remote-config)

### Key Features

Руководство рекомендует использовать действие "Request Remote Configuration" в паре с условиями успеха/отказа. Игры должны загружать флаги один раз при запуске для оптимальной производительности.

### Local Fallback

Разработчики должны внедрить значения по умолчанию, используя действие "Set Default Value for Key". Это обеспечивает продолжение игры при отказе запросов на сервер из-за проблем с сетью.

### Client Parameters

SDK поддерживает отправку параметров клиента через действие "Set Client Feature" при запросе удаленной конфигурации, позволяя персонализацию на стороне сервера.

### Value Retrieval

Полученные значения конфигурации доступны через функцию выражения "Flag" внутри SDK.

## 6. Лидерборды (construct-3/leaderboards)

### Submitting Scores

Действие "Send Score to Leaderboard" позволяет авторизованным игрокам отправлять очки со следующими параметрами:
- **Name**: Технический идентификатор лидербордов (string)
- **Score**: Значение очка игрока (number)
- **Extra Data**: Опциональные метаданные (string)

Важное ограничение: запросы могут отправляться не более одного раза в секунду.

### Retrieving Leaderboard Data

Действие "Request Leaderboard Table" извлекает рейтинги, используя:
- **Name**: Идентификатор лидербордов
- **Top Positions**: Количество запрашиваемых топ-записей
- **Include Player Position**: Boolean флаг
- **Surrounding Positions**: Записи выше/ниже игрока

## 7. Внутриигровые покупки (construct-3/in-game-purchases)

### Portal Currency

Платформа использует "Yan" (Ян) в качестве универсальной валюты во всех играх. Игроки могут пополнить баланс через банковские карты, с обменными курсами варьирующимися по странам.

### Purchase Types

Руководство различает два типа реализации:

1. **Non-Consumable Purchases** (e.g., ad removal): Получены один раз за игрока; проверьте статус покупки при каждом запуске игры
2. **Consumable Purchases** (e.g., in-game coins): Получены несколько раз; используйте метод "Consume Purchase" после успешных транзакций

### Implementation Process

Разработчики должны:
- Добавить покупки и опубликовать черновик в консоли разработчика
- Отправить письмо на games-partners@yandex-team.ru с названием и ID игры для включения покупок
- Ждать подтверждения перед тестированием и конфигурацией

## 8. Асинхронный мультиплеер (construct-3/multiplayer)

### Initialization

Используйте действие "Initialize Multiplayer" с параметрами для количества сессий (максимум 10), времени хода противника в миллисекундах и фильтрации метаданных.

### Session Recording

Два основных действия доступны — "Record Transaction" для логирования транзакций с JSON данными и "Save Session" для сохранения метаданных.

### Session Management

Разработчики работают с сессиями исключительно через события, используя триггеры как "Session Transactions Received" и "Session Ended." Система включает циклы для обработки отдельных транзакций и доступа к идентификаторам сессий.

## 9. Поддержка ТВ (construct-3/tv-support)

### Key Requirements

Игры должны соответствовать этим стандартам платформы ТВ:
- Возможность полноэкранного отображения
- Поддержка навигации с помощью стрелок на пульте
- Поддержка кнопок Back и OK

### Remote Control Implementation

Плагин предоставляет три метода взаимодействия:

1. **Condition**: "TV remote button pressed" — проверяет, нажата ли кнопка в данный момент
2. **Trigger**: "On TV remote button press" — срабатывает при нажатии кнопки игроком
3. **Trigger**: "On TV remote button release" — срабатывает при отпускании кнопки

Доступные кнопки: Up, Down, Left, Right и OK.

### Testing Tool

Встроенный эмулятор TV пульта активируется нажатием **F6** в режиме предпросмотра, позволяя разработчикам тестировать удаленное взаимодействие без физического оборудования.

## 10. Throttle и Debounce (construct-3/throttle-debounce)

### Key Concepts

**Throttle** ("Не чаще чем раз в <X> секунд") ограничивает, как часто выполняется код. Полезно для операций, требующих больших ресурсов, таких как вычисления физики или AI, которые реагируют на ввод пользователя.

**Debounce** ("На отложенное событие") откладывает выполнение функции до истечения установленной длительности с момента последней попытки срабатывания. Это предотвращает превышение ограничений частоты API при обновлении лидербордов или других методов SDK с ограничениями запросов.

## 11. Яндекс Метрика (construct-3/metrica)

### Setup

Для включения отслеживания разработчики должны настроить ID счётчика Metrica в разделе свойств плагина в Construct 3.

### Goal Tracking

Основная функция — это действие **Send Goal**, которое принимает два параметра:

- **Goal Name** (string): Идентификатор цели в Яндекс Метрике
- **Additional Goal Data** (JSON): Опциональные метаданные для сопровождения отправки цели

## 12. Локализация текста (construct-3/text-localization)

### Creating Translation Files

Процесс включает подготовку JSON файлов с кодами языков ISO 639-1. Разработчики должны организовать их в структуру `Files/i18n` с отдельными файлами, такими как `en.json` и `ru.json`, содержащими пары ключ-значение переводов.

### Using in Layouts

Текстовые объекты могут ссылаться на ключи переводов, используя нотацию скобок. При тестировании в режиме предпросмотра "система автоматической локализации может заменять текст внутри Text, Sprite Font и Adaptive Text объектов."

### Notable Features

- Нет необходимости в дополнительном кодировании для базовой локализации
- Поддерживает изменения текста во время выполнения
- Работает с несколькими типами текстовых объектов
- Совместимо с эффектами анимации

## 13. Локализация спрайтов (construct-3/sprite)

### Key Points

**Purpose**: Метод позволяет разработчикам создавать несколько локализаций спрайтов без изменения других элементов проекта.

**Prerequisites**: Файлы переводов должны быть созданы для всех требуемых языков перед реализацией локализации спрайтов.

### Implementation Steps

1. **Add animations** к спрайту, используя соответствующие коды языков
2. **Create the sprite** с новыми анимациями, соответствующими кодам целевых языков
3. **Ensure compliance**: Удалите любые анимации, которые не соответствуют допустимым кодам языков

**Testing**: Нажмите кнопку Play для предпросмотра изменений локализации в реальном времени на основе текущего языка игрока.
