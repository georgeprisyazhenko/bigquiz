# Эффективность генерации BigQuiz — воронка конверсии

Метрики полного цикла «генерация → судья → код-гейты → полиш → моё финальное ревью».
Цель — видеть, где теряется выход и сколько стоит один approved-вопрос, чтобы тюнить
пайплайн осознанно. Заполняется после каждой партии.

## Воронка по стадиям (что считать)

| Стадия | Метрика |
|---|---|
| Генерация | сгенерировано кандидатов = `perSubcat × подкатегорий` |
| Судья (Opus) | keep / revise / drop |
| Код-гейт при merge (длина/около/диапазоны) | сколько keep→revise понижено |
| В пул | keep + revise (drop не льётся) |
| Полиш (revise) | починено / без изм. / дроп / откат по гейту |
| Моё ревью | approved / rework / discard |
| **Итог** | **approved / сгенерировано = сквозная конверсия** |

## Партия 1 — 2026-06-24 (25 подкатегорий × 10, пустые/почти пустые)

**Воронка:**
| Стадия | Числа |
|---|---|
| Сгенерировано | **250** |
| Судья | keep 124 · revise 84 · **drop 42** (17%) |
| Код-гейт длины при merge | 13 keep → revise |
| В пул | **208** (keep 111 + revise 97); 42 dropped не влиты |
| Полиш revise (97) | починено 72 · без изм. 5 · дроп 5 · откат 5 → в пул 92, +3 ручная доводка длины |
| Пул до моего ревью | 203 pending (111 keep + 92 полир. revise) + 5 discard |
| **Моё ревью (203)** | **approved 155 · rework 39 · discard 9** |

**Ключевые конверсии:**
| Метрика | Значение |
|---|---|
| Сквозная: approved / сгенерировано | **155 / 250 = 62%** |
| Брак судьи (drop) | 42 / 250 = 17% |
| keep → мой approved | 83 / 111 = **75%** (28 keep я всё равно завернул) |
| revise → полиш → мой approved | 72 / 97 = **74%** (полиш догнал revise до уровня keep) |
| Ещё проблемные после всего пайплайна | rework 39 + discard 9 = 48 / 203 = **24%** |
| Полиш спас (approved из revise) | **72** вопроса (иначе ручная правка) |

**Стоимость (токены / время воркфлоу):**
| Воркфлоу | Агентов | Токены | Время |
|---|---|---|---|
| Генерация | 75 | ~3.68M | ~20 мин |
| Полиш #1 (97) | 85 | ~1.85M | ~9 мин |
| Полиш #2 (18, догон) | 30 | ~0.57M | ~11 мин |
| **Итого партия** | **190** | **~6.1M** | **~40 мин** |
| ≈ на 1 approved (155) | — | **~39k токенов** | — |

**Наблюдения:**
- Доминанта брака revise — антипаттерн «экзамен» (~70% причин судьи). Усилен genPrompt
  (вариант B) ПОСЛЕ этой партии — ожидаем падение revise на следующей.
- Полиш — ~40% токенов партии (~2.4M на ~92 спасённых, ~26k/шт). Главный кандидат на облегчение.
- keep→approved лишь 75%: вердикт судьи keep ≠ мой keep (судья мягче на 25%).
- Самопричинённые потери: не чистил polish-out между прогонами (двойной merge), polish
  не вернул 13/97 в первый раз. Лечится очисткой polish-in/out перед прогоном.
