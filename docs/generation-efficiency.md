# Эффективность генерации BigQuiz — воронка конверсии

Метрики полного цикла «генерация → судья → код-гейты → полиш → моё финальное ревью».
Цель — видеть, где теряется выход и сколько стоит один approved-вопрос, чтобы тюнить
пайплайн осознанно. Заполняется после каждой партии.

## Воронка по стадиям (что считать)

| Стадия | Метрика |
|---|---|
| Генерация | сгенерировано кандидатов = `perSubcat × подкатегорий` |
| Судья (Opus) | keep / revise / drop |
| Код-гейт при merge (длина/около/диапазоны) | сколько keep→revise понижено |
| В пул | keep + revise (drop не льётся) |
| Полиш (revise) | починено / без изм. / дроп / откат по гейту |
| Моё ревью | approved / rework / discard |
| **Итог** | **approved / сгенерировано = сквозная конверсия** |

дожимал 3 класса (класс-когерентность дистракторов, жаргон-в-ответе, падеж) → зашиты ПОСЛЕ R3.

**Ключевые конверсии (финал):**

| Полиш спас (approved из revise за 3 раунда) | первое ревью 155 → 182 = **+27** |
| Итог отсева | discard 23 (5 полиш + 18 моих) |

⚠️ **Полиш = 51% токенов партии** (больше, чем генерация). Многораундовая rework-петля — главный сток.
NB: машинное время ~50 мин; реальный elapsed (от запуска до сейчас) — много часов, но это в основном
ЧЕЛОВЕЧЕСКОЕ ревью (3 раунда) + ручные слияния, а не машина.

**Наблюдения / уроки:**
- Доминанта revise — антипаттерн «экзамен» (~70%). Усилен genPrompt (B) ПОСЛЕ партии.
- 3 класса брака из R3 (класс-когерентность, жаргон-в-ответе, падеж) зашиты в правила.

  (очистка polish-папок, merge-polish не откатывает, фиксы когерентны).
- Рычаги на следующую партию: B (↓revise), perSubcat 7, лёгкий полиш (без Proof), фактчек у судьи,
  хронические отскоки (**2+ раунда** по одному вопросу) чинить руками/дроп, а не 3-м полишем.
